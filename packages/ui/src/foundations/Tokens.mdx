# Tokens

Tokens give a shared name to a design choice. Choose the name by its purpose:
`--uix-text-primary` for readable text, `--uix-bg-surface` for a surface, or
`--uix-radius-control` for a control's corners. Components using those roles
follow changes to the brand and theme.

## Choose the scope of a change

| You want to change                         | Use                                               |
| ------------------------------------------ | ------------------------------------------------- |
| A design decision across the product       | A semantic role on the brand or application scope |
| One part of one component in an area       | That component's override slot                    |
| Space between items or the text-size scale | A spacing or font-size token                      |

Button's accent fill uses `--uix-accent`. Compare its states in the matrix,
including hover, focus, disabled and loading behavior:

<Canvas of={ButtonStories.Matrix} />

To change only the corners of medium buttons in a search area, set the Button
slot on that area:

```css
@layer overrides {
  .search-actions {
    --uix-button-radius: var(--uix-radius-pill);
  }
}
```

The component's slot falls back to `--uix-radius-control` when no value is set.
Small and large Button sizes use their own semantic radius roles. Check the
component's slot documentation before applying the same override to another
size or variant.

## Primitive

Primitive tokens hold palette values and scales. Brand mappings may use them to
assign semantic roles. Components use semantic or component tokens for colour,
radius, typeface and shadow so those choices remain configurable. Spacing and
font-size scales may be used directly.

The tables come from the token registry. Copy a token name with its button;
values are checked against the stylesheets during the build.

## Semantic

Semantic tokens describe use: text, surfaces, controls, status, focus and
layout. Override these roles when defining a brand. Adding a semantic role
changes the public API, so first check whether an existing role fits.

Some roles describe a relationship. `--uix-bg-raised` is lighter than the surface
behind it in both themes. `--uix-scrim` darkens a backdrop. `--uix-ink` and
`--uix-paper` change with the theme and are used inside `color-mix()` to shade a
fill; they are not substitutes for a readable foreground/background pair.

## Component slots

A component slot changes one documented part. The component supplies its default
where it reads the slot:

```css
background: var(--uix-button-accent-bg, var(--uix-accent));
```

Slots are listed in each component's Theming documentation, with their defaults.
They do not need global declarations. Keep overrides near the feature that uses
them, and inspect the affected states. A custom fill can require a different
foreground and can fall outside the library's registered contrast checks.

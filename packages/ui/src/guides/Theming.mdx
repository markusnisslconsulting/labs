# Theming

Use the existing brand mapping to give an application its fonts, colours and
shape. Choose light or dark appearance separately. Most applications can start
with those settings and use a component slot for a small local adjustment.

## Load the brand

Import these styles once, in this order, at the application entry:

```tsx
import "@labs/ui/styles.css";
import "@labs/brand/labs.css";
```

The adapter loads the local fonts and applies consulting roles to an unbranded
root. Use `data-brand="consulting"` when that mapping needs its own scope inside
another brand. The core UI package can also be used without the adapter when an
application supplies its own font delivery and brand mapping.

## Choose a theme

Set the theme and writing direction on the document root:

```html
<html lang="en" dir="ltr" data-theme="auto"></html>
```

`auto` follows the operating system. `light` and `dark` select a fixed scheme;
omitting the attribute selects light. The theme applies to the document. A
`data-theme` attribute on a nested panel does not provide an independent theme.

| Axis      | Attribute      | Supported settings                                                           |
| --------- | -------------- | ---------------------------------------------------------------------------- |
| Brand     | `data-brand`   | consulting default; explicit `consulting` with the brand adapter; `coaching` |
| Theme     | `data-theme`   | `light`, `dark`, `auto` on the root                                          |
| Density   | `data-density` | omit to inherit; `default`, `compact`, `comfortable`                         |
| Direction | `dir`          | `ltr`, `rtl`                                                                 |

## Scope a brand or density

Brand and density may apply to a section. The examples use the same components
with different roles. Change the theme toolbar to inspect both schemes:

<Canvas of={BrandStories.Comparison} />

A brand sets typography, shape, elevation and a default density. An explicit
density on the section or an ancestor takes precedence over that default:

```tsx
<section data-brand="consulting" data-density="compact">
  <Button>Save changes</Button>
</section>
```

Here `Button` is imported from `@labs/ui/components/Button`. Nested brand scopes
resolve their own accent aliases and density-derived spacing. Avoid adding a
brand attribute only to change colour: it can change type and geometry too.

Omit `data-density` to inherit the containing scope or use the brand's default.
Use `data-density="default"` to reset a nested section to the normal spacing
scale, even inside a compact page. The Storybook toolbar's **Default** option
removes its override and restores the brand default.

Density adjusts control heights, internal spacing and layout gaps. It does not
scale text, icons, avatar diameters or skeleton placeholders. A component's size
prop remains independent of density. Menu, Popover, Tooltip, Dialog, AlertDialog,
Drawer and CommandPalette retain their containing `data-brand` and
`data-density` scopes when opened in a portal. Selector-based application
styles and local custom-property overrides still need to target the popup.

## Set writing direction

Use the same direction for the DOM and the interaction provider:

```tsx
import { DirectionProvider } from "@labs/ui";

<DirectionProvider direction={direction}>
  <div dir={direction}>{children}</div>
</DirectionProvider>;
```

The DOM attribute controls layout. The provider controls directional behaviour
in composite widgets, including tabs and positioned overlays. Set both at the
application root; repeat both for a section that uses the opposite direction.
Storybook's direction toolbar sets them together. Direction does not translate
content: supply the appropriate strings separately.

Leave the root font size under the reader's control. The rem-based type and
control scales respond to it. Control-height tokens have a 24 CSS-pixel floor,
but clipped controls, spacing and the surrounding layout still need inspection.

## Override one component

Use a documented component slot for a local change. For example, medium buttons
inside this area can use the pill radius while other controls keep their shape:

```css
@layer overrides {
  .search-actions {
    --uix-button-radius: var(--uix-radius-pill);
  }
}
```

Check the component's supported sizes and states. If changing a fill, also
check its foreground, hover, disabled and focus treatment. A custom colour pair
may not be covered by the library's contrast report.

## Supply a custom mapping

Keep an application's mapping in its own stylesheet and import it after the
library styles. Override semantic roles in `@layer overrides`:

```css
@layer overrides {
  [data-brand="editorial"] {
    --uix-font-display: var(--uix-font-serif);
    --uix-weight-display: var(--uix-font-weight-regular);
    --uix-radius-control: var(--uix-radius-inset);
    --uix-elevation-raised: none;
  }
}
```

This example changes a few roles and inherits the others. A complete brand must
set every role that should differ from its containing scope. A font-family value
selects a face; load and license any required font files separately.

Only a mapping maintained as part of the library belongs under its
`styles/brands/` directory. Applications do not need to edit the library to
supply their own mapping. Keep semantic additions deliberate and component
styles inside `@layer components`.

## Check the result

Inspect a reading sample, a form, a primary action and an error state. Check both
themes, the actual containing brand, narrow layout, larger text and keyboard
focus. Compare the result in Docs and in the story canvas.

`pnpm nx run ui:contrast-report` reports the registered pairings. Run
`pnpm gates` for the complete checks. Neither command measures every colour
combination that application content and custom overrides can create.

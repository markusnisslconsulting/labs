# Contributing

Start with the task the reader needs to complete. Check the generated inventory
for an existing component, compound part or slot that provides the behavior.
Choose the smallest change that can be used and verified independently.

## Change an existing component

Read its usage guidance, props, states and keyboard contract. Keep existing
consumers in mind when changing behavior or an exported type. Describe any
compatibility impact in the changelog and update the relevant examples.

Use semantic or component tokens for colour, corners, typeface and shadow.
Keep stylesheet rules in `@layer components`, register new component slots and
read each with its semantic fallback. Prefer a component slot to a new semantic
role when the change concerns one part of one component.

## Compose a pattern or page

Use layout components to arrange shared controls. Keep content, validation and
service state in the feature that owns the task. Extract a reusable pattern
when the arrangement and behavior recur; accept content and children where
consumers need different wording or structure.

## Add a primitive

A new primitive needs a responsibility that existing components and compositions
cannot provide. Keep its public contract consistent with the library:

- Provide the complete controlled/uncontrolled value contract when both modes
  are offered. Uncontrolled state must update every value the control displays.
- Use Field's returned control props for a custom text-like control. Choice
  controls use the field-message helper with their own label layout.
- Read default user-facing strings, including accessible labels, from the library
  string provider. Application content remains with the consuming feature.
- Document keyboard behavior and cover it with matching browser events. Check
  accessible names, descriptions and state as well as axe results.

## Write useful stories

Reference stories show meaningful uses and variants. Choose one matrix story
per component for visual snapshots, with
`chromatic: { disableSnapshot: false }`. Other stories inherit the disabled
snapshot default unless an explicit exception applies.

Interaction tests use `tags: ["!dev"]` so a tested resting state does not appear
as another catalogue example. This complete story file tests the label behavior:

```tsx
import type { Meta, StoryObj } from "@storybook/react-vite";
import { expect, userEvent } from "storybook/test";
import { Checkbox } from "@labs/ui/components/Checkbox";

const meta = {
  title: "Examples/Email preference",
  component: Checkbox,
  argTypes: { checked: { control: false } },
  args: {
    label: "Email updates",
    defaultChecked: false,
    disabled: false,
    indeterminate: false,
    required: false,
  },
} satisfies Meta<typeof Checkbox>;
export default meta;
type Story = StoryObj<typeof meta>;

export const TogglesFromTheLabel: Story = {
  tags: ["!dev"],
  play: async ({ canvas }) => {
    const control = canvas.getByRole("checkbox", { name: "Email updates" });
    await userEvent.click(canvas.getByText("Email updates"));
    await expect(control).toBeChecked();
  },
};
```

Give each exposed boolean control an explicit initial value in `args`. Keep
controlled examples synchronized with Controls, and avoid exposing competing
controlled and initial-state props. Events remain in the Docs table while being
excluded from Controls. Use explicit `fn()` callbacks when asserting calls.

## Verify the change

```sh
pnpm gates
pnpm nx run ui:visual-sweep
```

The gate command is shared with CI. The visual sweep creates images for review;
it does not compare them with an approved baseline. Inspect relevant states,
themes, widths and keyboard behavior in Docs and Canvas. Record any native or
manual accessibility checks that still need to happen.

Use the contrast, token, story-coverage and size reports when investigating a
specific result. Follow the Deprecation guide when replacing a public token.

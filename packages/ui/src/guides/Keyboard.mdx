# Keyboard

Use the keyboard to complete the same task as someone using a pointer. Every
action needs a reachable control, visible focus and a predictable next position.
The table below lists the keys supported by each component.

## Follow focus through a composition

Begin outside the example. Tab into it, move forward and backward, activate an
action, then leave the example again. Check that the order follows the content
and that a sticky header or open layer does not hide the focused control.

For menus, dialogs and other layers, check both entry and exit. Closing a layer
should return focus to an appropriate control. A form error summary should let
you reach the field that needs attention without searching for it again.

## Distinguish focus from selection

Some widgets let the reader explore before committing. Tabs use manual
activation: arrow keys move focus between tabs; Enter or Space activates the
focused tab. Check the focused tab and selected panel separately. Do not make
an expensive action run just because focus moved.

Use the documented behavior for the particular control. A native checkbox,
slider and radio group have different keyboard contracts; replacing them with
clickable containers would require rebuilding that behavior.

## Check both writing directions

In horizontal tabs and toolbars, arrows follow the visible order: Left advances
in RTL and Right advances in LTR. A tree expands toward its inline end and
collapses toward its inline start. Calendar arrows move to the adjacent visible
date. Up and Down retain their vertical meaning.

Set both the DOM direction and `DirectionProvider`, as shown in Theming. Check
nested sections and open overlays as well as the document root.

## Component and browser behavior

The owner column distinguishes component/Base UI handlers from native browser
behavior. Styling and wrappers can interfere with either, so both are covered
by browser tests using trusted key events.

Native Select and datalist Combobox typeahead also depend on platform pickers.
The test exceptions are recorded in `api.spec.ts`; DOM assertions do not verify
the operating system's picker UI. Check those interactions on the target
platform before relying on them in a task.

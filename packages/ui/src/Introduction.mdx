# Labs UI

Welcome to the component workbench for the labs at
[labs.markusnissl.com](https://labs.markusnissl.com). This is not a
scrapbook of one-off demos; it is the design system those demos are
built from, reviewed in isolation.

Everything this page claims is enforced by a test. That is the point:
a design system is persuasive exactly as far as its promises are
executable, and prose is not a guarantee.

## The token hierarchy

Three tiers, each with one job.

- **Primitive** — raw values, no opinion: the palette, radii, spacing,
  type and motion scales. No component may name a primitive **colour,
  radius, typeface or shadow**. Those four are what a theme or a brand
  remaps, so a component that names one has put itself out of their
  reach permanently. This rule used to cover colour alone, and the
  sentence that replaced this one said the radius and type scales "may
  be used directly" — which is precisely why `ocean` could only ever
  re-point a hue. Spacing and font *size* stay open: they are a rhythm
  the whole library shares. Tests read the component stylesheets, so
  each rule is checked where it actually breaks rather than in the
  registry's own declarations.
- **Semantic** — intent, and not only colour: `--uix-text-primary`,
  `--uix-bg-page`, `--uix-accent`, `--uix-status-ok`, and alongside them
  the shape roles (`--uix-radius-control`, `--uix-radius-container`,
  `--uix-radius-pill`), the type roles (`--uix-font-body`,
  `--uix-font-display`, `--uix-font-code`) and the elevation roles
  (`--uix-elevation-raised`, `--uix-elevation-overlay`,
  `--uix-elevation-modal`). This is the only layer a brand touches, so
  whatever a brand must be able to change has to have a role here. `--uix-ink` and `--uix-paper` name the two ends of the
  neutral ramp for the current theme, so a component can shade a fill
  by mixing toward them and get the right result on light and dark
  without naming either colour.
- **Component** — per-part override slots: `--uix-button-accent-bg`,
  `--uix-chip-active-bg`, `--uix-panel-radius`. These are deliberately
  **not declared** anywhere. Each is referenced as
  `var(--uix-button-accent-bg, var(--uix-accent))`, so the slot exists
  as an override point and costs nothing until something fills it. It
  is why the tier can grow to cover every component without the
  stylesheet growing with it.

`src/tokens.registry.ts` is the machine-readable counterpart — name,
value, tier, intent, and an optional `deprecated` note mirroring
DTCG's `$deprecated`. A parity test fails the build when the registry
and the CSS disagree, in either direction.

## Brands

A brand is data, not a stylesheet edit. One file under
`styles/brands/`, containing only semantic overrides, imported from
`styles.css`. Adding a brand touches no core file, which is the
property that makes multi-brand scale — brands cannot collide in a
shared file.

`ocean` overrides exactly one token, `--uix-accent`. Everything that
should follow the accent already does: `--uix-accent-soft` mixes from
it and `--uix-focus-ring` aliases it, so a new brand cannot forget
them. A test asserts that a brand file declares nothing but semantic
tokens.

`graphite` exists because one token was not proof of anything. It
re-points shape, display face, elevation and accent: corners come down
to near-square, headings take a serif, and shadows are replaced by
hairlines. Same components, one file, no core stylesheet edited. Open
**Foundations / Brands** to see all three at once — that page is pinned
to the three brands rather than following the toolbar, because a column
that followed the toolbar was a duplicate of a control already on
screen.

Switch brand, theme and density from the toolbar above; each is an
independent axis on the root element (`data-brand`, `data-theme`,
`data-density`) rather than a separate build.

## Density, and the reader's own text size

`data-density="compact"` sets one multiplier, and the semantic
`--uix-gap-*` roles carry it into padding, gaps and margins alike — not
only the inside of controls. At the default density they resolve to the
raw scale exactly, so cozy rendering is unchanged.

Control heights are `max(24px, calc(<rem> * var(--uix-density)))`. The
rem half means a reader who sets their browser text larger gets larger
controls, which is what the unit is for; `font-size` is therefore set on
`body` and never on `html`, because pinning the root size cancels that
setting. The `24px` half is the one absolute length in the token layer:
WCAG 2.2 target size is specified in CSS pixels, and at the compact
multiplier of 0.72 the small height resolved to 23.04px. Clamping in the
token rather than raising the multiplier means a product that sets its
own density cannot reintroduce the violation.

A browser test measures every matrix story against the control tokens at
two densities and two root font sizes, reading the token values out of
the page rather than asserting pixels. Growing past the floor is allowed
— that is what a long label at 20px does — and clipping is not.

## The floor under all of it

`styles/reset.css` is the normalization layer, and for a long time there
was none: `base.css` set a typographic voice and was mistaken for a
foundation, so every user-agent default reached the components
untouched. Nothing set `box-sizing`, which meant every `min-height` in
the library was a floor on the *content* box and any bordered control
came out two pixels over the scale. Three separate reports about things
not being centred were that one omission.

The two files are deliberately separate. `reset.css` holds the box
model, inheritance, and the places where engines still disagree, and
every rule there names the browser that needs it. `base.css` holds only
choices someone could reasonably make differently. It is not
normalize.css, which mostly corrects browsers nobody ships any more.

## CSS ships with the component

There is no single stylesheet to import. `styles.css` is the global
floor and nothing more: the token tiers, the brands, and element
defaults. Every component imports its own CSS, so a page that renders
a `Badge` downloads `Badge.css` and nothing else.

That works because `styles.css` declares the cascade order once:

```css
@layer tokens, base, components, overrides;
```

A component stylesheet arriving late — in a lazily loaded route chunk —
still lands in `@layer components`. It cannot out-rank the tokens, and
it cannot beat a product's `overrides`, whatever order the network
happens to deliver. Without that declaration, split CSS would be
decided by load order, which is the kind of bug that only reproduces on
a cold cache.

Import per component to keep the benefit:

```ts
import { Button } from "@labs/ui/components/Button";
```

The barrel (`@labs/ui`) re-exports everything and is convenient, but a
CSS import is a side effect, so the barrel pulls every component's
styles. Use it for prototypes, not for pages you measure.

## The component API

Every component takes the attributes of the element it renders.
`className` **merges** with the component's own class rather than
replacing it, and everything else lands on the root, so `id`,
`data-*`, `aria-*`, event handlers and refs all work. Base UI roots
keep their function form of `className` too.

The one exception is `Tooltip`, which renders no element of its own —
its trigger is the caller's element, so there is nothing to pass
attributes to. That is documented on the component.

## What the build refuses

Each of these closes a claim this page used to make in prose. Several
were added after the claim turned out to be false.

- **Token parity** — the registry and the CSS cannot disagree, in either
  direction, and no component stylesheet may name a colour, radius,
  typeface or shadow primitive, or hardcode a colour or a pixel radius.
- **Docs pages** — every one of the forty is loaded in a browser and
  must render. Components/Button had been dead for days with
  "t.startsWith is not a function" while all 145 story tests were green,
  because the runner replays stories and nothing had ever opened a docs
  page. The cause was an un-backticked `<a href />` in a TSDoc comment:
  markdown made it a real anchor, and Storybook's link renderer calls
  `href.startsWith`, which a valueless attribute does not have. The bug
  was in the prose, so no amount of story coverage could have found it.
- **The control scale** — every matrix story measured against the
  control tokens across density and root font size, with the token
  values read out of the page. The first version of this asserted
  32/40/48px, which describes exactly one configuration.
- **Narrow** — nothing overflows at 360px, and what reads as one row
  stays one row.
- **Icons** — no component draws an icon with a text character. A glyph
  is positioned by the font's metrics rather than by its box, so it
  cannot be centred from CSS.
- **Disabled** — a `disabled` prop and disabled styling imply each other
  in *both* directions. One direction alone let Switch ship a rule that
  could never match Base UI's `<span role="switch">`, and let Tabs ship
  styling for a state no tab could enter.
- **Snapshotted stories do not mutate** — a story that clicks in
  `play()` and is photographed baselines the state after the click under
  a name that promised the state before it. Two were doing exactly that.
- **Contrast** — every declared pairing is measured in every theme and
  every brand, 144 of them, against WCAG AA. A brand may pick a hue; it
  may not pick a pairing nobody can read. This caught an inverted
  surface that was legible inside itself and invisible against the page
  it sat on.
- **Token usage** — reachability over the alias graph, so "is anyone
  still using this" is answered by the graph rather than by grep, plus a
  ratchet that fails on a new use of a deprecated token and on a
  baseline that was not tightened after one was removed.
- **Root font size and colour scheme** — `font-size` is never set on the
  root element, and each theme declares its `color-scheme`. Both are
  silent when broken: the first cancels a reader's text-size setting,
  the second leaves a dark page with a light scrollbar and a white date
  picker.
- **Story coverage** — derived from each component's own types: every
  union value rendered, every state boolean shown, one assertion, and a
  keyboard story if the component is operable. Turning it on found 33 of
  34 components with no keyboard test.
- **Accessibility** — axe on every story, and separately on every page
  of the labs site, because composition is where component-level
  accessibility stops seeing.
- **Cascade order** — the layer declaration is prepended to every
  emitted stylesheet and then asserted, because the source having it
  was not the same as the bundle having it.

## Stories: reference or interaction, never both

A reference story shows a state and does not change it. An interaction
story drives behaviour and opts out of snapshots, because Chromatic
captures the frame after `play()` resolves — a story that clicks its own
control baselines the state after the click under a name that promised
the state before it. Two deliberate exceptions keep their snapshots:
Focus and Dialog, where the ring and the open dialog are the picture
worth having.

Every story is snapshotted in both themes. Brand coverage is set on
Foundations / Brands, where a brand difference is the subject.

## Accessibility

The a11y addon runs with `test: "error"`, and the test runner replays
every story headless in CI with axe injected, failing the run on a
violation. Stories opt out per story with `parameters.a11y.disable`
and narrow rules with `parameters.a11y.config.rules` — the same shape
the panel reads, so CI and the panel never disagree.

Interaction tests assert semantics directly: a filter chip toggles
`aria-pressed`, a panel is reachable as a named region, a disabled
button keeps its accessible name. Colour is never the only channel —
`StatusPill` puts the state in words and leaves the dot decorative.

`Button`'s `loading` state uses `aria-disabled`, not the native
attribute: a disabled button leaves the tab order, so a user tabbing a
form would lose their place the moment a button started loading.

## Where to start

Open **Foundations / Tokens** for all three tiers, then
**Components / Button** for a full state matrix. Flip the brand and
theme toolbars on any story — that is the whole multi-brand mechanism,
visible.

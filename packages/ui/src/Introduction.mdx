# Labs UI

Welcome to the component workbench for the labs at
[labs.markusnissl.com](https://labs.markusnissl.com). This is not a
scrapbook of one-off demos; it is the design system those demos are
built from, reviewed in isolation.

## The token hierarchy

Three tiers, each with one job. Components bind only to the top two;
a product rebrands by overriding the semantic layer in one file.

- **Primitive** — raw values, no opinion: the palette, radii and
  spacing scale. Never referenced by components directly.
- **Semantic** — intent: `--uix-text-primary`, `--uix-bg-page`,
  `--uix-accent`, `--uix-status-ok`. This is the layer a product
  overrides to rebrand without forking the system.
- **Component** — per-part bindings: `--uix-button-bg`,
  `--uix-chip-active-bg`, `--uix-panel-radius`. What a product may
  theme on one component without touching any other.

The machine-readable registry lives in `src/tokens.registry.ts`, and
a parity test fails the build when the registry and the CSS drift
apart — so code generators and AI assistants can consume tokens
without parsing stylesheets.

## The parts

- **Components** — the accessible primitives: `Button`, `Chip`,
  `StatusPill`, `Panel`. Each documents its keyboard behaviour and
  what assistive technology hears.
- **Patterns** — compositions the labs site itself uses: `LabCard`,
  `SearchInput`. Product-shaped, built from primitives only.
- **Demos** — the article exhibits, composed from primitives.

## Accessibility

The a11y addon checks every story with `test: "error"` — a finding
fails the story. The test runner replays all stories headless in CI,
so violations block deploys instead of shipping. Interaction tests
assert semantics directly: a disabled button keeps its accessible
name, a filter chip toggles `aria-pressed`, a panel is reachable as
a named region.

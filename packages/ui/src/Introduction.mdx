# Labs UI

Build a page by composing controls, layout components and patterns. This
workbench contains **{facts.componentCount} components**, with examples you can

Start with the example below. It combines a Checkbox, Button and Stack into a

## Use a component

The packages are workspace libraries. In an application in this repository,
import the global styles once at the entry point. Add the brand adapter to load
the local fonts and consulting mapping:

```tsx
import "@labs/ui/styles.css";
import "@labs/brand/labs.css";
```

The UI library also works without the brand adapter, using its default font
stacks and tokens. Declare the packages your application imports in its own
manifest. A separate application needs the built package artifacts; these
examples do not assume a package published to a public registry.

## Build a page

Choose components by the work they do. Use TextField for a labelled text input,
Form for fields submitted together, and a layout component to place them.
Stack spaces items vertically; Cluster wraps a row; Columns reduces the column
count as the available width narrows. Container limits the page's width, and
Section groups a heading with its content.

Keep content, validation and service calls in the feature that owns the task.
Extract a pattern when the same arrangement and behavior recur. A screen then
composes those patterns with the appropriate content and state.

Open a component's Docs page for its API and usage guidance. The Controls panel
lets you change a story, and Code shows its source. Matrix stories collect
related states for comparison. Interaction tests remain in the test run without
adding duplicate examples to the sidebar.

## Tokens and overrides

Use semantic roles for colour, corners, typeface and shadow. A role such as
`--uix-accent` follows the selected brand and theme. A component slot such as
`--uix-button-accent-bg` changes only that part of the component. Spacing and
font-size scales provide the shared rhythm between components.

The global stylesheet establishes this layer order:

<pre>
  <code>{`@layer ${facts.layers.join(", ")};`}</code>
</pre>

Put application styling in `@layer overrides` and component rules in
`@layer components`. Normal declarations in later layers take precedence over
normal declarations in earlier layers. Unlayered rules take precedence over all
of those layers. The Tokens reference explains the available roles and slots.

## Themes and brands

The theme toolbar changes light, dark or system-following appearance. Set
`data-theme` on the document root in an application. Brand changes are separate:
the brand controls typography, colour and shape, while the theme controls the
light/dark scheme.

Use the brand and density toolbars to compare examples, then check them in a
narrow viewport and with larger text. The Theming guide shows how to apply the
same settings to an application and to a section within it. For translated UI,
provide component strings through `LabsStrings` and set the document's `dir`.

## Package measurements

Component imports include their required styles. The global stylesheet supplies
tokens, reset, element defaults and print styles. Both the package barrel and
component subpaths are supported; the isolated consumer check compares their
output for the same fixture.

| Measurement                                   | Gzip size                                     |
| --------------------------------------------- | --------------------------------------------- |
| Global stylesheet and its imported styles     | {(facts.globalStyles / 1024).toFixed(2)} KiB  |
| Median component, internal JavaScript and CSS | {(facts.median / 1024).toFixed(2)} KiB        |
| Largest component: {facts.largest.name}       | {(facts.largest.total / 1024).toFixed(2)} KiB |

These measurements sum separately gzipped package files, following static
relative imports and counting shared files once per component. They exclude
external dependencies such as React and Base UI. Components can share files, so
adding these figures does not predict an application's download size. Measure
its final bundle as well. `pnpm size-report` gives the component breakdown.

## Verification

Use `pnpm gates` before handing off a change. It runs the shared local and CI
checks for contracts, interaction, accessibility fixtures, package output and
size budgets. Inspect relevant examples in Docs and Canvas as well; a passing
assertion does not establish that a composition is easy to use.

The Accessibility guide describes the checks and their limitations. `pnpm nx run ui:visual-sweep` captures examples for visual review.
